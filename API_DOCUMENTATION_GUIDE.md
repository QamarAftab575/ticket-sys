# API Documentation Guide

## Overview

This API provides comprehensive documentation using a multi-layered approach:

1. **Scramble** - Automatic OpenAPI generation from Laravel code
2. **Scalar UI** - Beautiful interactive documentation
3. **OpenAPI YAML** - Manual specification for complex scenarios
4. **Markdown Guides** - Implementation and quick start guides

## Installation Steps

### Step 1: Install Dependencies

```bash
composer require dedoc/scramble
```

### Step 2: Publish Configuration

```bash
php artisan vendor:publish --tag=scramble-config
```

### Step 3: Access Documentation

After installation, documentation is available at:

**Development**:
```
http://localhost:8000/api/docs
```

**Production**:
```
https://yourapp.com/api/docs
```

## Documentation Stack

### 1. Scramble (OpenAPI Generation)

**What it does**: Automatically generates OpenAPI 3.1 specification from your Laravel controllers

**Features**:
- ✅ Automatic endpoint discovery
- ✅ Request/response schema generation
- ✅ Validation rules documentation
- ✅ Authentication schemes
- ✅ Error responses
- ✅ Real-time updates (no manual sync needed)

**Configuration**: `config/scramble.php`

### 2. Scalar UI

**What it does**: Beautiful, modern API documentation interface

**Features**:
- ✅ Interactive API explorer
- ✅ Try-it-out functionality
- ✅ Code examples in multiple languages
- ✅ Dark/light mode
- ✅ Search functionality
- ✅ Mobile responsive

**Access**: Automatically integrated with Scramble

### 3. OpenAPI Specification

**What it does**: Industry-standard API specification format

**Features**:
- ✅ Machine-readable format
- ✅ Import into Postman/Insomnia
- ✅ Client SDK generation
- ✅ API contract validation
- ✅ Version control friendly

**File**: `openapi.yaml` (manual) or auto-generated by Scramble

## Documentation Structure

### Endpoint Documentation Format

Each endpoint is documented with:

#### 1. Route Information
```
Method: POST
Path: /api/v1/workspaces
Tag: Workspaces
Summary: Create Workspace
```

#### 2. Authentication Requirements
```
Security: BearerAuth (required)
Authorization: Only authenticated users
```

#### 3. Request Payload
```json
{
  "name": "Engineering Team",
  "description": "Main engineering workspace",
  "avatar_color": "#3B82F6"
}
```

#### 4. Validation Rules
```
name: required|string|max:255
description: nullable|string|max:1000
avatar_color: nullable|string|regex:/^#([A-Fa-f0-9]{6}|[A-Fa-f0-9]{3})$/
```

#### 5. Success Response
```json
{
  "message": "Workspace created successfully",
  "data": {
    "id": "9d3e4b1a-7f8c-4d2e-9a1b-3c4d5e6f7a8b",
    "name": "Engineering Team",
    "description": "Main engineering workspace",
    "avatar_color": "#3B82F6",
    "is_active": true,
    "created_at": "2024-03-15T10:30:00Z",
    "updated_at": "2024-03-15T10:30:00Z"
  }
}
```

#### 6. Error Responses
```json
401 Unauthorized:
{
  "message": "Unauthenticated",
  "error": "Missing or invalid API token"
}

403 Forbidden:
{
  "message": "Forbidden"
}

422 Validation Error:
{
  "message": "Validation failed",
  "errors": {
    "name": ["The name field is required."]
  }
}
```

## HTTP Status Codes

### Success Codes
- `200 OK` - Successful GET/PUT request
- `201 Created` - Successful POST request
- `204 No Content` - Successful DELETE request

### Client Error Codes
- `400 Bad Request` - Invalid request format
- `401 Unauthorized` - Missing or invalid authentication
- `403 Forbidden` - Insufficient permissions
- `404 Not Found` - Resource not found
- `422 Unprocessable Entity` - Validation error
- `429 Too Many Requests` - Rate limit exceeded

### Server Error Codes
- `500 Internal Server Error` - Server error

## Authentication Documentation

### Token-Based Authentication

All protected endpoints require authentication using one of these methods:

#### Method 1: Bearer Token (Recommended)
```http
GET /api/v1/users/me HTTP/1.1
Host: yourapp.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

#### Method 2: Custom Header
```http
GET /api/v1/users/me HTTP/1.1
Host: yourapp.com
X-API-Token: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

#### Method 3: Query Parameter
```http
GET /api/v1/users/me?api_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... HTTP/1.1
Host: yourapp.com
Content-Type: application/json
```

### Getting a Token

1. **Login**:
```bash
curl -X POST https://yourapp.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "john@example.com",
    "password": "Password123"
  }'
```

2. **Response**:
```json
{
  "message": "Login successful",
  "user": { ... },
  "token": "your-api-token-here"
}
```

3. **Use Token**:
```bash
curl -X GET https://yourapp.com/api/v1/users/me \
  -H "Authorization: Bearer your-api-token-here"
```

## Versioning Strategy

### Current Version: v1

All endpoints are prefixed with `/api/v1/`

### Future Versions

When breaking changes are needed:
1. Create new route file: `routes/api_v2.php`
2. Create new controllers: `app/Http/Controllers/Api/V2/`
3. Update Scramble config to document both versions
4. Maintain v1 for backward compatibility

### Deprecation Notice

Deprecated endpoints will:
1. Return `Deprecation: true` header
2. Show warning in documentation
3. Include alternative endpoint in response
4. Be maintained for 6 months minimum

## Examples

### Example 1: Create Workspace and Project

```bash
# Step 1: Login
TOKEN=$(curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"password"}' \
  | jq -r '.token')

# Step 2: Create Workspace
WORKSPACE_ID=$(curl -X POST http://localhost:8000/api/v1/workspaces \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Engineering","description":"Engineering team workspace"}' \
  | jq -r '.data.id')

# Step 3: Create Project
PROJECT_ID=$(curl -X POST http://localhost:8000/api/v1/projects \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"organization_id\":\"$WORKSPACE_ID\",\"name\":\"API Project\",\"manager_id\":\"user-id-here\"}" \
  | jq -r '.data.id')

echo "Created project: $PROJECT_ID"
```

### Example 2: Create Task with Custom Fields

```bash
# Create custom field
FIELD_ID=$(curl -X POST http://localhost:8000/api/v1/projects/$PROJECT_ID/custom-fields \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Priority","type":"dropdown","options":["Low","Medium","High"]}' \
  | jq -r '.data.id')

# Create task
TASK_ID=$(curl -X POST http://localhost:8000/api/v1/projects/$PROJECT_ID/tasks \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Implement API","priority":"high","due_date":"2024-12-31"}' \
  | jq -r '.data.id')

# Set custom field value
curl -X POST http://localhost:8000/api/v1/tasks/$TASK_ID/custom-fields/$FIELD_ID/value \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value":"High"}'
```

## Troubleshooting

### Documentation Not Accessible

**Problem**: Can't access `/api/docs`

**Solutions**:
1. Run `composer install` to install Scramble
2. Clear route cache: `php artisan route:clear`
3. Clear config cache: `php artisan config:clear`
4. Check `config/scramble.php` exists

### Endpoints Not Showing

**Problem**: Some endpoints not appearing in documentation

**Solutions**:
1. Ensure controllers are in correct namespace
2. Check route prefix in `config/scramble.php`
3. Verify middleware configuration
4. Clear application cache

### Authentication Not Working

**Problem**: "Try it out" fails with 401

**Solutions**:
1. Ensure token is valid and not expired
2. Check token format (no extra spaces)
3. Verify bearer token header format
4. Test token with curl first
